# Unit Toggles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Global unit preferences (distance, speed, altitude, temperature, time) that the user changes by tapping any value or in Profile → Units.

**Architecture:** Pure formatter/convert functions + enums in `lib/formatters/units.dart`; `UnitsNotifier` (ChangeNotifier, shared_preferences) provided at app root; `UnitCycle` widget in `lib/ui/components/` wraps any value and cycles its dimension on tap; `AeroSegmented` for the settings section. Surfaces switch to formatters inside `UnitCycle`.

**Tech Stack:** Flutter, provider, shared_preferences, timezone, intl, animated_flip_counter, flutter_test.

**Spec:** `docs/superpowers/specs/2026-11-21-units-design.md`

## Global Constraints
- Defaults: km, kt, ft, °C, airport local time — output must equal today's for defaults.
- All new UI follows `app/DESIGN.md` (tokens, AeroPressable, AeroMotion, no Material defaults). `flutter test` (incl. `design_rules_test.dart`) must pass; regenerate the baseline when a touched file's count drops.
- Huge files (`flight_info.dart`, `profile/stats/main.dart`, `airport_details_sheet.dart`): change unit values only. Small touched files: migrate fully.
- Visual check (DESIGN.md §7) for map bar, settings section and summary card before claiming done.

## Review Focus
- FL for altitudes below ~1,000 ft / on ground → show `FL000`? Expected: below 1,000 ft show feet even in FL mode (ground ops are never in FL). (Task 1 test)
- Invalid / empty airport timezone with "airport local" → falls back to UTC `Z` instead of throwing. (Task 1 test)
- 12h device setting + UTC mode → still 24h `HH:mmZ`. (Task 1 test)
- Prefs missing or holding an unknown enum name (future rename) → defaults, no crash. (Task 2 test)
- Rapid repeated taps → each tap advances exactly one step; no double toast. (Task 3 test)

### Task 1: Unit enums, conversion and formatting

**Files:**
- Create: `app/lib/formatters/units.dart`
- Delete: `app/lib/utils/distance.dart` (unused)
- Test: `app/test/units_format_test.dart`

**Interfaces:**
- Produces:
  - `enum DistanceUnit { km, mi, nm }`, `enum SpeedUnit { kt, kmh, mph }`, `enum AltitudeUnit { ft, m, fl }`, `enum TempUnit { c, f }`, `enum TimeMode { airport, device, utc }`, `enum UnitDimension { distance, speed, altitude, temperature, time }`.
  - `T nextOf<T extends Enum>(List<T> values, T current)` (wraps).
  - `String unitLabel(Enum unit)` → `km`, `mi`, `nm`, `kt`, `km/h`, `mph`, `ft`, `m`, `FL`, `°C`, `°F`, `airport time`, `your time`, `UTC`.
  - `num convertDistance(num km, DistanceUnit u)`, `num convertSpeed(num kt, SpeedUnit u)`, `num convertAltitude(num ft, AltitudeUnit u)` (fl → ft/100), `num convertTemp(num c, TempUnit u)`.
  - `String formatDistance(num km, DistanceUnit u)` → `6,819 km` (grouped, rounded), `String formatSpeed(num kt, SpeedUnit u)` → `558 kt`, `String formatAltitude(num ft, AltitudeUnit u)` → `39,000 ft` / `11,887 m` / `FL390` (below 1,000 ft in FL mode → feet), `String formatElevation(num ft, AltitudeUnit u)` (FL → ft), `String formatTemp(num c, TempUnit u)` → `21°C` / `70°F`.
  - `String formatTime(DateTime utc, {required String? airportTz, required TimeMode mode, required bool use24})`: airport → in airport tz (fallback UTC on bad tz); device → `toLocal()`; utc → `HH:mm` + `Z`. 12h format `h:mm a`, 24h `H:mm` (matches existing `toTimezoneString`).
